Self-hosted

Este sitio no vive en la nube de nadie más. Corre en mi propio homelab, de punta a punta — por control, por aprendizaje y por gusto.

el stack
// edge

Cloudflare al frente

DNS, CDN y una capa de protección antes de que cualquier petición llegue a casa. El origen nunca se expone directamente.

// tls

HTTPS automático

Un reverse proxy gestiona los certificados de Let's Encrypt y los renueva solo. Todo el tráfico va cifrado, sin intervención manual.

// app

Estático sobre Docker

La web es HTML y CSS servidos por nginx dentro de un contenedor. Rápido, ligero y sin base de datos que exponer: menos superficie, menos que romper.

// deploy

Despliegue agéntico

No subo archivos a mano. Flujos de n8n (con MCP) aplican los cambios por mí y verifican la integridad de cada archivo por checksum antes de publicarlo.

seguridad

La arquitectura, no el mapa

Los detalles que de verdad importan — direcciones internas, puertos, nombres de host y credenciales — se quedan en casa. Lo que cuento aquí es cómo está pensado el sistema, no cómo entrar en él.

Self-hosting no significa exponerlo todo: significa decidir exactamente qué sale a internet y qué no. Esa frontera es parte del diseño.
