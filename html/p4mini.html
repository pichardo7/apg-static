// hardware · iot

P4mini

Una pantalla montada sobre ESP32-P4 que muestra, en tiempo real, un dashboard de monitoreo de red — sin nube, sin app, sin Home Assistant de por medio.

esp32-p4 · esphome · lvgl
qué es

Un dashboard que vive en una pantalla, no en un navegador

P4mini es una pantalla táctil de 480×800 (board JC4880P443, touch GT911) sobre un ESP32-P4, configurada con ESPHome. Muestra en vivo el dashboard de monitoreo — problemas activos, incidentes recientes y uso de ancho de banda — todo dibujado con widgets nativos de LVGL en una sola página con scroll.

No corre un navegador ni renderiza capturas de pantalla: pide un JSON pequeño, lo parsea y pinta los valores directamente sobre labels y badges de color. Tampoco usa la integración de Home Assistant — se decidió explícitamente dejarla fuera, porque el dashboard no tiene nada que ver con domótica.

arquitectura

Cuatro saltos, sin renderizado de por medio

ESP32-P4 (LVGL) → webhook de n8n → API de Grafana → Postgres

Cada 45 segundos el ESP32 pide el JSON al webhook. n8n consulta la base de datos directo por la API de Grafana (/api/ds/query) y regresa un resumen ya armado — nada de renderizar imágenes ni capturas. El dispositivo solo dibuja lo que recibe.

// display

Una página, no pestañas

Las cuatro secciones (resumen, problemas, incidentes, ancho de banda) van apiladas en un único contenedor scrolleable de LVGL — sin tabview, para mantenerlo simple y confiable.

// datos

JSON chico, sin imágenes

El payload trae el resumen más hasta cinco filas por sección. Se actualizan los widgets directo dentro del mismo callback de parseo, sin variables intermedias — patrón que salió de descartar un bug de filas que no se refrescaban.

// backend

n8n como intermediario

Un workflow de n8n hace de puente entre el dispositivo y Grafana: consulta Postgres vía la API de datasources de Grafana y entrega un JSON ya resumido, autenticado por header.

decisiones

Por qué no es una captura de pantalla

La primera versión mostraba un screenshot completo del dashboard de Grafana, renderizado en el servidor y descargado por el ESP32. Se abandonó por dos razones concretas: le exigía a Grafana un render headless cada dos minutos, y en pruebas de campo de poco más de una hora casi la mitad de las descargas fallaba o se colgaba — una vez incluso disparó el watchdog del dispositivo y lo reinició.

Los workflows de esa etapa siguen guardados en n8n, desactivados en vez de borrados, por si algún día vale la pena retomar un enfoque híbrido. Por ahora, un JSON chico pintado con widgets nativos es más rápido y muchísimo más confiable que mover una imagen completa cada par de minutos.

— construido a prueba y error, con el log del dispositivo como fuente de verdad
